## 4. 两家共同点提炼（对 SARibbon 最有约束力的结论）

1. **命令式注册是 Qt5/Qt6 双版本的现实解**。KDDW 2.0.1（`QT_MIN_VERSION "6.2.0"`，明知 qt_add_qml_module 可用而不用，CMakeLists.txt:146 + QmlTypes.cpp:21-30）与 QWK 1.0.1（src/quick/ 零 QT_VERSION 分支，qwkquickglobal.cpp:14-25 + README.md:246）在 Qt6 下都只用 `qmlRegisterType` 族 + 应用侧 load 前显式调用。**约束力**：v2 §5.3 单轨化、04 S1 是唯一执行路径——执行时不得因"Qt6 应该用新机制"的直觉动摇；声明式轨只能按 3.1+ 候选 B-3 的触发条件启用。
2. **C++ 结构类 + QML 视觉层的混合模式被两家生产库同时验证**。KDDW 提供"C++ 宿主 + QML 叶子"的完整实证（宿主类模式、握手属性、Base-视觉两层、叶子三部曲、析构 deleteLater，§3.3 表）；QWK 提供"纯 C++ 库 + QML 应用侧配合 + 命令式注册"的工程组织实证（§2 表）；两家的示例侧都是"普通可执行 + qml 进 qrc + 链库"、零 qt_add_qml_module。**约束力**：v2 §9-D5 混合模式路线的合法性已确认，04 S3 的骨架是照抄级模式，执行 agent 无需（也不应）发明新形态。
3. **边界与纯净性靠机制保障，不靠自觉**。KDDW 的 layouting 净室 = 窄契约 + 平台数值全数据化 + 前端宏裁剪（较弱形式——core 整体仍有 widget 触点）；QWK 的模块边界 = QT_LINKS 显式声明 + 单 export set 链接传播。SARibbon 取更强组合：三库物理隔离 + 模块层 CI 扫描（含 `<QtWidgets/` 路径形式）+ 引擎确定性层定向 grep + 组合构建矩阵（Widgets=OFF Qml=ON/OFF）。**约束力**：v2 §3.7 两层门禁与 01 S9/S10、02 S8-3 是验收硬门，扫描不过 = 该步失败，不存在"下不为例"。
4. **测试黄金值/一致性套件是一致性承诺的唯一可执行保障**。KDDW 用"真实录制 JSON fixture + 关系不变量 + 每操作 checkSanity/失败自动 dumpLayout + fatal_logger 零容忍"保障引擎正确性；QWK 上游用"ctest --no-tests=error + consumer 测试注册核对"防 CI 假绿。**约束力**：02 S5.0（录制先于一切改动、黄金值全程零修改）、02 S8（矩阵四类补强）、04 S7（跨前端一致性套件）、01 S10-7/03 S5-4（防空转）环环相扣，任何执行环节都不得裁剪测试步骤来赶工期——"行为零变化"与"双端一致"两个 3.0 核心承诺全靠它们兑现。
